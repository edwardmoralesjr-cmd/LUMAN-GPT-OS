# Three Futures — Delivery and GitHub Sync Protocol

## Canon Status

**Locked Workflow Rule**

This protocol governs every future writing session for *Three Futures*.

## Required Delivery After Every Completed Writing Artifact

Whenever a new manuscript artifact is completed, including a prologue, chapter, interlude, revised chapter, scene, appendix, or compiled manuscript section, LUMAN must complete all of the following before treating the writing session as finished:

1. Save the approved Markdown manuscript text inside `BOOKS/three-futures/04_DRAFTS/` on the active Three Futures GitHub branch.
2. Run the Three Futures Canon Guardian audit appropriate to that artifact.
3. Save the audit inside `BOOKS/three-futures/07_CANON_GUARDIAN/AUDITS/`.
4. Update the project status and manuscript frontier when the artifact changes project progress.
5. Update the active GitHub pull request or branch summary when necessary.
6. Create a professionally formatted Microsoft Word `.docx` version of the completed writing.
7. Render and visually inspect every page of the Word document before delivery.
8. Provide Edward with a direct downloadable link to the verified Word document in the same response that reports completion.

## Word Document Rules

Each Word delivery should:

- contain the complete approved writing artifact
- preserve chapter and section titles
- use clean publishing-style typography and readable spacing
- avoid internal GitHub notes, tool citations, audit text, or drafting metadata unless Edward requests them
- include the book title and author attribution when appropriate
- use a clear filename containing `Three_Futures`, the artifact name, and its current status
- be regenerated whenever the manuscript text receives a substantive revision

## GitHub Authority Rule

The Markdown manuscript stored in GitHub remains the canonical editable source. The Word file is the portable delivery copy generated from that source.

When the GitHub manuscript and a Word delivery conflict, the most recently approved GitHub manuscript governs unless Edward explicitly promotes the Word revision back into canon.

## Session Completion Rule

A writing session is not complete until both conditions are met:

- the approved manuscript and related canon updates are saved to GitHub
- the verified Word document download link has been delivered to Edward

## Current Application

This protocol applies immediately to the completed Prologue, `The Sixth Chair`, and to every future chapter beginning with Chapter 1, `Arrival`.
