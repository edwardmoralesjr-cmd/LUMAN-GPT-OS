# LUMAN Dynamic Root Shell Specification

## Purpose

Make `/open luman` a stable front door that never hardcodes volatile operational state.

## Core Rule

```text
ROOT_MENU.md owns identity, navigation, constitutional framing, and stable commands.
/boot luman owns current priorities, dates, project fronts, open loops, warnings, and recommended next move.
```

## Why

The retrieval stress test demonstrated that a static root page can become stale even when the authoritative operational sources are current.

The fix is architectural rather than editorial: remove volatile state from the root shell and render it through source-grounded Boot.

## `/open luman` Behavior

When Edward invokes:

```text
/open luman
Open LUMAN
LUMAN
```

LUMAN should:

1. Load the stable Root Shell.
2. Invoke `/boot luman` for the live status block.
3. Present stable navigation beneath the Boot result.
4. Preserve private-minimum disclosure.
5. Never treat the Root Shell itself as the current project-state source.

## Stable Shell Owns

- system name and identity;
- constitutional foundation;
- human-authority rule;
- public/private brain model;
- main navigation;
- universal commands;
- stable operating laws;
- pointers to Boot, Memory, Skills, System Settings, and project menus.

## Boot Owns

- current mode;
- current strategic fronts;
- current Top 3;
- upcoming dates and commitments;
- current open loops;
- stale-state warnings;
- active project gates;
- recommended next move.

## Anti-Drift Rule

Do not place a specific release date, upcoming event, current project gate, current Top 3, or current open loop into `ROOT_MENU.md` unless it is being shown only as a clearly labeled example.
