# LUMAN OS Source-of-Truth Matrix

## Purpose

This file defines which source owns each type of information inside LUMAN OS and what wins when sources disagree.

It distinguishes constitutional governance authority from domain-specific content authority so that a project source can own facts without outranking Edward's human authority or the Human Sovereignty Constitution.

## Governance Authority Order

For authority over LUMAN behavior, delegation, goals, and system governance, use:

```text
1. Applicable law, platform safety, and unavoidable external constraints
2. Edward's explicit current instruction within those constraints
3. Human Sovereignty Constitution
4. System Settings governance and Autopilot Operating Law
5. Master Command Center and routing protocols
6. Project-specific operating laws and modules
7. Historical conventions, inferred preferences, and defaults
```

A lower layer must not silently override a higher layer.

## Content Source Authority Order

For factual, canonical, project, and record truth inside a domain, use this order unless a project-specific canon file defines a stricter content rule:

```text
1. Published or explicitly Locked Canon material for that domain
2. Explicitly approved current source-of-truth file
3. Current project continuity, registry, or active module file
4. Current GitHub status and command files
5. Edward's explicit current factual correction or project decision
6. Saved memory and prior conversation summaries
7. Historical drafts, legacy alternatives, and archived files
8. Inference
```

Content authority does not create moral or personal authority. A manuscript may own canon truth; a financial statement may own account truth; neither may define Edward's values or goals.

A newer timestamp alone does not create authority. A copied or recently modified historical document may still be outdated.

## Creative Ecosystem Authority Rule

```text
The Creative Ecosystem Engine owns relationship suggestions, gap analysis, stagnation analysis, transformation options, and task-ranking logic.
It does not own lyrics, manuscripts, canon, release metadata, personal records, project activation decisions, or Edward's goals.
```

Suggested relationships remain noncanonical until approved. A high synthesis score does not outrank project truth, current strategic priorities, privacy rules, Canon Guardian findings, or the Human Sovereignty Constitution.

## Chat, Memory, and GitHub Roles

### Chat

```text
Living intelligence layer
```

Use for reasoning, creation, decision support, tool operation, and active updates.

Chat may infer and recommend, but consequential inferences remain contestable and should not silently become durable truth.

### Memory

```text
Continuity and personalization layer
```

Use for durable preferences, active project context, and relevant life facts. Memory is not a substitute for detailed canon files, manuscripts, ledgers, or source documents.

When remembered information materially affects a consequential judgment, it should remain reviewable rather than being treated as unquestionable fact.

### GitHub

```text
Durable public-safe external brain
```

Use for commands, governance, project structures, public-safe status, templates, canon systems, and reusable knowledge. Do not store secrets or private ledgers.

Prior disclosure to LUMAN does not create automatic permission for public persistence.

## Conflict Classification

When two sources disagree, classify the conflict as:

```text
Presentation Drift         = menus or commands describe the same function differently
Status Drift               = project stage or next action differs
Version Conflict           = competing drafts or structures claim current authority
Canon Contradiction        = two story facts cannot both be true
Ownership Ambiguity        = no source clearly owns the information
Privacy Boundary Conflict  = useful information is unsafe for public storage
Synthesis Overreach        = a suggested connection is being treated as source truth or canon without approval
Constitutional Drift       = system behavior or lower-level governance conflicts with the Human Sovereignty Constitution
Authority Transfer         = AI recommendation, inference, or automation is being treated as human decision without proper delegation
```

## Resolution Procedure

1. Determine whether the conflict is about governance authority or domain content truth.
2. Identify the conflicting statements.
3. Cite the source path and authority level of each.
4. Check for explicit approval, publication, Locked Canon status, or current human instruction as appropriate.
5. Apply the Human Sovereignty Constitution to behavioral or authority conflicts.
6. Select a content winner only when source authority is clear.
7. Preserve the losing version as archived history when useful.
8. Record unresolved conflicts instead of silently choosing.
9. Update routing, registry, continuity, and changelog files as needed.
10. Reject or relabel suggestions that exceed their authority.

## Non-Negotiable Security Rule

Never commit credentials, encryption seeds, account numbers, live balances, private medical records, confidential employer data, or sensitive family records to the public repository.
