# LUMAN OS System Settings Commands

## Purpose

This file defines the command surface for the System Settings and Master Command Center layer under the Human Sovereignty Constitution.

## Constitutional Commands

### `/constitution`

Open:

```text
LUMAN_OS/system_settings/HUMAN_SOVEREIGNTY_CONSTITUTION.md
```

Return the governing question, root human authority, ten sovereignty tests, decision classes, cognitive roles, precedence rules, and amendment rule.

### `/sovereignty audit`

Use the Sovereignty Guardian:

```text
LUMAN_OS/system_settings/modules/sovereignty_guardian/MODULE_MANIFEST.md
```

Evaluate the requested workflow, module, decision, automation, or system against:

1. Meaningful Agency
2. Informed Understanding
3. Real Consent and Refusal
4. Contestability and Remedy
5. Capability and Independence
6. Cognitive and Data Sovereignty
7. Relational Integrity
8. Pluralism and Equal Dignity
9. Distributed Power and Accountability
10. Human Goal Authority

Allowed ratings:

```text
PASS
CONDITIONAL
FAIL
NOT APPLICABLE
```

For CONDITIONAL or FAIL, include the smallest useful remediation.

### `/authorship check`

Determine:

```text
Whose goal initiated the work?
Who supplied the core meaning or intent?
What did LUMAN generate, infer, organize, or recommend?
What meaningful selections or revisions were made by Edward?
Could Edward reject or substantially change the result?
Did the interaction increase Edward's capability?
Who retains final authority?
```

### `/mirror`

Reflect patterns, assumptions, emotions, contradictions, recurring themes, and stated values without claiming decision authority.

### `/architect`

Convert scattered information, goals, projects, and ideas into coherent systems, structures, maps, and workflows.

### `/challenge`

Actively test assumptions, identify disconfirming evidence, separate fact from inference, surface blind spots, and construct strong counterarguments.

### `/execute`

Perform bounded authorized work while preserving scope, privacy, reversibility where appropriate, and reporting.

### `/steward`

Protect memory, provenance, continuity, privacy, versioning, source authority, and the distinction between public-safe and private information.

### `/decision`

Provide decision support without replacing Edward as the decision-maker.

For consequential choices, prefer:

```text
Objective
Known facts
Important assumptions
Uncertainty
Options
Tradeoffs
LUMAN recommendation, if useful
Strongest counterargument, if material
Decision authority: Edward
```

## Primary Commands

### `/system settings`

Open:

```text
LUMAN_OS/system_settings/SYSTEM_SETTINGS_MENU.md
```

Show constitutional status, governance menu, current system state, integrity warning, and recommended next move.

### `/open command center`

Open:

```text
LUMAN_OS/system_settings/MASTER_COMMAND_CENTER.md
```

Return:

1. Current mode
2. Human-foundation check
3. Active strategic fronts
4. Shipping gate
5. Deep-building gate
6. Integrity or sovereignty warning when material
7. Open loops
8. Recommended next move
9. Human decision boundary when consequential

### `/system audit`

Open the latest integration audit:

```text
LUMAN_OS/system_settings/INTEGRATION_AUDIT_2026-07-10.md
```

Review architecture, ownership, privacy boundaries, unresolved conflicts, and synchronization state.

Use `/sovereignty audit` when the question is specifically whether LUMAN preserves agency, authorship, consent, contestability, capability, or human goal authority.

### `/source map`

Open:

```text
LUMAN_OS/system_settings/SOURCE_OF_TRUTH_MATRIX.md
```

Use when modern modules, legacy vaults, chat, memory, canon, assets, or archived files disagree.

### `/project registry`

Open:

```text
LUMAN_OS/system_settings/PROJECT_REGISTRY.md
```

Show project state, primary owner, dependency, and next gate.

### `/90 day path`

Open:

```text
LUMAN_OS/system_settings/90_DAY_EXECUTION_PATH_2026-07-10.md
```

Show the current execution period, three active strategic fronts, phase gates, and exit criteria.

### `/autopilot law`

Open:

```text
LUMAN_OS/system_settings/AUTOPILOT_OPERATING_LAW.md
```

Apply default classification, routing, sovereignty, privacy, canon, project-activation, and next-best-action rules.

Autopilot remains subordinate to the Human Sovereignty Constitution.

### `/integration status`

Compare:

```text
LUMAN_OS/system_settings/HUMAN_SOVEREIGNTY_CONSTITUTION.md
LUMAN_OS/system_settings/MASTER_COMMAND_CENTER.md
LUMAN_OS/system_settings/PROJECT_REGISTRY.md
00_CORE/ACTIVE_PRIORITIES.md
00_CORE/OPEN_LOOPS.md
LUMAN_OS/ROOT_MENU.md
```

Report any status drift, constitutional drift, or routing mismatch.

### `/system next move`

Choose one action using this order:

1. Preserve human sovereignty and protect the human foundation.
2. Complete the current shipping gate.
3. Resolve a blocking dependency.
4. Prevent contradiction or information loss.
5. Advance the approved deep-building gate.

A recommended next move is not automatically a human decision unless bounded execution has already been delegated.

## Creative Ecosystem Commands

Primary module:

```text
LUMAN_OS/system_settings/modules/creative_ecosystem_engine/
```

### `/open creative ecosystem`

Open the module manifest, governance, current integration gate, and command reference.

### `/synthesize`

Find meaningful cross-project relationships. Return suggestions as noncanonical until approved.

### `/pivot`

Recommend a related task that acts as active recovery without abandoning the larger mission or violating the three-front limit.

### `/evolve`

Classify proposed work as evolution, refinement, repetition risk, or disconnected work.

### `/recycle`

Find dormant, archived, completed, or published material with unrealized transformation value.

### `/gaps`

Identify missing musical, literary, visual, practical, philosophical, family-learning, or worldbuilding counterparts.

### `/next`

Rank actions by project priority, momentum, cross-project value, dependency value, emotional alignment, completion probability, anti-stagnation value, time fit, and burnout risk.

Ranking is advisory and must not silently redefine Edward's goals.

### `/lineage`

Trace where a concept originated and how it has transformed through the ecosystem.

### `/ecosystem`

Show ecosystem health, project balance, synthesis opportunities, gaps, dormant nutrients, and stagnation risk.

### `/transform`

Propose a governed transformation of existing material into another medium or project form.

### `/stagnation-check`

Detect blocked work, theme repetition without evolution, excessive active-node load, neglected high-value material, and creation-integration imbalance.

## Portfolio Commands

### `/active fronts`

Show the current three-front portfolio.

### `/activate project: [name]`

Before activation, verify:

- Project home
- Current source owner
- Reason to activate now
- Next gate
- Definition of done
- Capacity within the three-front limit
- No blocking unresolved dependency
- No material conflict with a higher human priority

### `/incubate project: [name]`

Capture the project without adding it to current execution priorities.

### `/archive project: [name]`

Preserve history, remove it from active execution, and update the registry.

### `/project gate: [name]`

Return the project's current state, next gate, dependency, and definition of done.

## Integrity Commands

### `/check drift`

Check for:

- Presentation drift
- Status drift
- Version conflict
- Canon contradiction
- Ownership ambiguity
- Privacy boundary conflict
- Constitutional drift
- Unclear authority transfer

### `/resolve ownership: [topic]`

Identify all possible source owners and recommend one explicit owner with bridge references for secondary locations.

### `/privacy check`

Verify that proposed GitHub content contains no credentials, live financial details, private medical records, employer-confidential data, sensitive family records, or unnecessary private identifiers.

Also verify that prior disclosure is not being treated as automatic permission for public persistence.
