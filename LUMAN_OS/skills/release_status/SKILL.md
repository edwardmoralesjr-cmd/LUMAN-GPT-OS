# Skill: Release Status

## Purpose

Give a source-grounded status check for a music, book, content, or software release without confusing planned, uploaded, scheduled, live, or historical states.

## Command

```text
/release status: [release]
```

## Sovereignty Class

Class B — Supported Judgment.

## Procedure

1. Identify the release and owning project source.
2. Verify the intended release date against the current date.
3. Distinguish states:
   - concept
   - assets in progress
   - assembly
   - distribution/upload unverified
   - scheduled/confirmed
   - released/historical
   - blocked
4. Read connected platform/account sources only when authorized and available.
5. Check metadata, artwork, audio/manuscript/build, explicit/content labels, credits, promo assets, and known platform gates as relevant.
6. Never infer distributor/platform acceptance from a local plan alone.
7. Surface the smallest next gate that materially reduces release risk.

## Output Contract

```text
RELEASE STATUS — [name]

TARGET DATE
...

STATE
...

CONFIRMED COMPLETE
- ...

UNVERIFIED / OPEN
- ...

RISKS
- ...

RECOMMENDED NEXT MOVE
...

Decision authority: Edward
```

## Freshness Rule

A past target date cannot remain labeled upcoming without evidence that the release was rescheduled.
