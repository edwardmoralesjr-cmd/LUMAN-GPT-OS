# Skill: Project Review

## Purpose

Review one project from its current source-of-truth files and return a concise operating picture: current state, what changed, blockers, stale claims, next gate, and one recommended action.

## Command

```text
/project review: [project]
```

## Sovereignty Class

Class B — Supported Judgment.

## Procedure

1. Identify the project owner/source hierarchy.
2. Retrieve current project status and relevant recent changes.
3. Apply freshness rules to dates and gates.
4. Separate current truth from archived/historical material.
5. Identify completed, active, blocked, stale, and unresolved items.
6. Check whether the project should remain active under the current strategic-front limit.
7. Recommend one next gate without silently activating a new project or changing canon/release intent.

## Output Contract

```text
PROJECT REVIEW — [name]

STATE
...

WHAT CHANGED
- ...

CURRENT GATE
...

BLOCKERS / UNCERTAINTY
- ...

OPEN LOOPS
- ...

RECOMMENDED NEXT MOVE
...

Decision authority: Edward
```

## Rules

- Project-specific sources outrank aggregate summaries for content truth.
- Newer verified state outranks older status prose.
- Do not infer completion from silence.
- For canon projects, preserve Locked / Working / Unresolved distinctions.
- For release projects, do not claim distributor/platform status without a source.
